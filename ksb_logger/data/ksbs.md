- **S3-5**: Link code to data sets
  - *Explanation*: This is about making your software interact with stored information. You'll learn how to write code that can read, write, and update data in various formats, such as files (like CSVs or JSONs), databases (like SQL or NoSQL), or through web APIs. This skill is essential for building dynamic applications that can save and retrieve information.
- **S5-8**: Conduct a range of test types, such as Integration, System, User Acceptance, Non-Functional, Performance and Security testing
  - *Explanation*: This means going beyond basic bug hunting. You'll learn how to perform different kinds of tests to ensure all parts of the software work together (Integration), that the whole system meets requirements (System), that it meets the user's needs (User Acceptance), and that it's fast, reliable, and secure (Non-Functional, Performance, and Security).
- **S8**: Create simple software designs to effectively communicate understanding of the program
  - *Explanation*: This is about being able to draw simple diagrams and write clear descriptions that explain how a piece of software works. You'll learn to use tools like flowcharts, wireframes, and user stories to visually communicate your ideas to both technical and non-technical people, ensuring everyone has a shared understanding of the program's design and functionality.
- **S9**: Create analysis artefacts, such as use cases and/or user stories
  - *Explanation*: This is about translating requirements into clear, concise descriptions that guide development. You'll learn to write user stories, which capture a user's goal, and use cases, which detail the steps to achieve that goal. These "artefacts" are essential for ensuring that the development team understands what to build and why.
- **S13**: Follow testing frameworks and methodologies
  - *Explanation*: This is the practical application of K12. It means you can actively use testing frameworks and methodologies to write and execute tests, find bugs, and ensure the quality of the software you are building.
- **S14**: Follow company, team or client approaches to continuous integration, version and source control
  - *Explanation*: This means using the tools and processes that allow a development team to work together on the same codebase without chaos. You'll learn how to use version control (like Git) to track changes and collaborate with others, and continuous integration (CI) to automatically test code and ensure that new changes don't break anything. This is a crucial skill for working in a modern software team.
- **S15**: Communicate software solutions and ideas to technical and non-technical stakeholders
  - *Explanation*: This is about being able to explain your work and ideas to different audiences. You'll learn how to present a technical solution to other developers, and how to explain the same solution in simple terms to a non-technical manager or client. The goal is to ensure everyone understands the value and impact of your work.
- **S17**: Interpret and implement a given design whist remaining compliant with security and maintainability requirements
  - *Explanation*: This means taking a blueprint for a piece of software and turning it into working code. It's not just about making it work, but also about making it secure from potential threats and easy to update and maintain in the future. You'll learn to write code that is not only functional but also robust, safe, and easy for other developers to work with.

  - *Explanation*: This means you can be trusted to work on your own and take ownership of your tasks.
